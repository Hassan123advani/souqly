# API contract — Phase 5 (seller onboarding + Seller Center core) & Phase 6 (cart, checkout, orders)

Conventions from CLAUDE.md apply. All `/seller/*` routes: `requireAuth` + `storeContext` + `requirePermission(...)`; storeId ONLY from `req.store`.

## Phase 5 — Seller onboarding
- `GET /stores/slug-available?slug=` → `{ data: { available, reason?: 'invalid'|'reserved'|'taken', suggestion? } }` (rate limited).
- `POST /seller/onboarding` (requireAuth only; user must not already own a store) body:
  `{ name, slug, tagline?, categoryIds[], themeColor, logo?: {url,key}, banner?: {url,key}, contact: {email, phone, whatsapp?}, pickupAddress: AddressInput, business: { type: 'individual'|'company', legalName, cnicOrRegNo, ntn?, idDocument?: {url,key} }, payout: { method: 'bank'|'jazzcash'|'easypaisa', accountTitle, accountNumber, bankName?, iban? }, policies?: {shipping, returns, warranty}, acceptTerms: true }`
  → creates Store `status: 'pending'` + StoreMember OWNER, sets `user.isSeller = true`, `activeMode = 'seller'`. `business.cnicOrRegNo` and `payout.accountNumber/iban` are encrypted at rest (AES-GCM helper) and only ever returned masked (`****1234`). Audit log. Notifies admins (in-app notification once Phase 7 exists; for now audit + console email to ADMIN_EMAIL).
- Upload during onboarding uses `POST /account/uploads` (requireAuth, images ≤ 5MB) — or allow `/seller/uploads` for users without a store? → **Decision: `POST /uploads/temp`** (requireAuth, images/pdf ≤ 5MB, folder `tmp/{userId}`), referenced by key in onboarding.
- `GET /seller/store` → full own store incl. masked business/payout, `status`, `rejectionReason`, onboarding checklist `{ logo, banner, firstProduct, policies, payout, shipping }` booleans.
- `PATCH /seller/store` (STORE_SETTINGS_MANAGE): name/tagline/description/logo/banner/themeColor/contact/policies/seo/layoutTemplate/sections/holidayMode/categoryIds. Slug change allowed once per 30 days.
- `PATCH /seller/store/payout` (STORE_FINANCE_MANAGE), `PATCH /seller/store/business` (OWNER only) → sets status back to `pending` re-review if store was `rejected`.
- `POST /seller/store/mall-request` → `mallRequested: true`.

## Seller Center core
- Dashboard: `GET /seller/dashboard?range=7d|30d|90d` → `{ kpis: { sales, orders, visitors, conversion, avgOrderValue } with deltas, salesSeries: [{date, sales, orders}], todo: { toConfirm, toPack, toShip, returnRequests, lowStock, unansweredQuestions, unreadChats }, healthScore: { score, factors: [{key, value, weight}] }, recentOrders[] }`.
- Products (exist from Phase 3) + `GET /seller/products?status=&q=&cursor=` with counts per status tab.
- Inventory: `GET /seller/inventory?lowStock=1&q=` (variant rows: product, sku, options, stock, reserved, warehouse stock), `POST /seller/inventory/adjust { productId, variantId, warehouseId?, delta, reason: 'restock'|'damage'|'correction'|'return'|'other', note? }` (atomic `$inc`, never below 0) → creates `StockMovement {storeId, productId, variantId, warehouseId, delta, reason, note, ref?: {type:'order'|'pos'|'adjustment', id}, actorId, balanceAfter}`; `GET /seller/inventory/movements?productId=&cursor=`; Warehouses CRUD `/seller/warehouses` (`{storeId, name, address, isDefault}`; variant stock per warehouse stored in `Product.variants[].warehouseStock: [{warehouseId, qty}]`, total `stock` = sum). Low-stock threshold per store setting (default 5).
- Staff & roles: `GET /seller/staff`, `POST /seller/staff/invite { email, role | customRoleId }` (existing user by email → StoreMember `status: 'invited'`, they accept via `POST /seller/invitations/:id/accept`; unknown email → console email with signup link), `PATCH /seller/staff/:memberId`, `DELETE /seller/staff/:memberId` (cannot remove OWNER), custom roles `GET/POST/PATCH/DELETE /seller/roles` (`{storeId, name, permissions: store.* only}`), `GET /seller/activity?cursor=` (store-scoped audit log).
- Settings: shipping `GET/PUT /seller/settings/shipping` → `{ zones: [{ name, cities: string[] | 'all', rate, freeAbove?, etaDays: [min,max] }], processingDays }`; notifications prefs; chat quick replies/auto-reply (Phase 8 uses them).

### Phase 5 — as built (deviations & additions, see D-047..D-054)
- `GET /stores/slug-available` slug rules: `SLUG_REGEX` (3-40, `a-z0-9-`, no leading/trailing/double dash) → `invalid`; `RESERVED_SLUGS` → `reserved`; `suggestion` always offered when unavailable.
- `POST /uploads/temp` (multipart field `file`): image (jpg/png/webp/avif) or PDF by magic bytes, ≤ 5 MB → `{ url, key, mimetype, size }`, key under `tmp/{userId}/`. Onboarding `logo/banner/business.idDocument` must reference the caller's own tmp keys (`INVALID_MEDIA`). `PATCH /seller/store` media may use `stores/{storeId}/` or the caller's `tmp/` keys.
- Onboarding errors: 409 `ALREADY_SELLER`, 409 `SLUG_UNAVAILABLE {reason, suggestion?}`, 400 `INVALID_CATEGORY`. `categoryIds` 1-10. Response = `SellerStore` (same as `GET /seller/store`). Admin email to `ADMIN_EMAIL` (console fallback).
- `GET /seller/store` also returns `myRole`, `myPermissions`, `slugChangedAt?`; `rejectionReason` only while `rejected`. `GET /seller/store`, `PATCH /seller/store/payout|business` work for **rejected** stores (resubmit → `pending`); every other `/seller/*` route returns 403 `STORE_SUSPENDED` for rejected/suspended stores. Slug change too soon → 429 `SLUG_CHANGE_TOO_SOON {nextChangeAt}`. `POST /seller/store/mall-request` needs `store.settings.manage` and an approved store.
- Admin (minimal): `POST /admin/stores/:id/approve`, `POST /admin/stores/:id/reject { reason (5-500) }` — `admin.stores.manage`, only from `pending` (else 409 `STORE_NOT_PENDING`), audited, owner emailed.
- Dashboard permission `store.dashboard.view`. KPI shape `{ value, previous, deltaPct | null }`; `conversion` is a percentage (orders / visitors × 100); `recentOrders: [{ id, number, status, total, itemCount, createdAt }]` (last 5). Order metrics are 0 until the Phase-6 `Order` model is registered.
- Inventory: list/movements/warehouses GET need `store.products.view`; adjust + warehouse writes need `store.inventory.manage`. Inventory rows: `{ productId, variantId, title, slug, image?, sku, options, stock, reserved, available, lowStock, warehouseStock[] }`; cursor `${productId}_${variantId}`. Adjust → `{ balanceAfter, movementId }`; 404 foreign product/variant/warehouse, 409 `INSUFFICIENT_STOCK`. `StockMovement.reason` also allows `sale | cancel | transfer` (order/POS flows). Phase 6 imports `adjustStock()`, `recordMovement()`, `recomputeTotalStock()` from `server/src/modules/inventory/inventory.service.ts`.
- Staff/roles/activity need `store.staff.manage`. Invite body `{ email, role }` XOR `{ email, customRoleId }` (role ∈ MANAGER|INVENTORY|ORDERS|MARKETING|CASHIER|RIDER) → `{ status: 'invited', member }` or `{ status: 'email_sent' }` (unknown email; nothing stored). Invitee: `GET /seller/invitations`, `POST /seller/invitations/:id/accept|decline` (204). `PATCH /seller/staff/:id { role? | customRoleId?, status?: 'active'|'disabled' }`. Path param is `:id` (member id). Custom-role members have `role: 'CUSTOM'`. Roles can only grant permissions the actor holds (403 `PERMISSION_NOT_GRANTABLE`); a role in use cannot be deleted (409 `ROLE_IN_USE`).
- Settings: `GET/PUT /seller/settings/shipping` (store.settings.manage, PUT replaces), `GET/PUT /seller/settings/notifications { newOrderEmail, newOrderSound, lowStockEmail, lowStockThreshold }` (merge), `GET/PUT /seller/settings/chat { quickReplies[], autoReply {enabled, message} }` (store.chat.manage, merge). Phase 6 imports `getShippingSettings(storeId)` from `server/src/modules/seller/storeSettings.service.ts`.
- Phase-4 gaps: `ProductCard.defaultVariantId?`, store summary `city?` on product detail, facets computed without their own filter, `DELETE /search/history/:q` (204).

## Phase 6 — Cart
Server cart for logged-in users; guest cart in localStorage merged on login.
- `GET /cart` → `{ data: { groups: [{ store: {id, slug, name, logo, isMall}, items: [CartItem], subtotal, shipping, storeVoucher? }], summary: { itemsSubtotal, shippingTotal, discountTotal, platformVoucher?, total, savings }, freeShippingProgress: [{storeId, remaining}], issues: [{itemId, type: 'out_of_stock'|'price_changed'|'qty_reduced'|'unavailable'}] } }`
- `CartItem = { id, productId, variantId, slug, title, image, options, price, compareAtPrice?, qty, maxQty, selected, savedForLater }`.
- `POST /cart/items { productId, variantId, qty }`, `PATCH /cart/items/:id { qty?, selected?, savedForLater? }`, `DELETE /cart/items/:id`, `POST /cart/select-all { selected }`, `POST /cart/merge { items: [{productId, variantId, qty}] }`.
- Vouchers: `POST /cart/vouchers { code }` / `DELETE /cart/vouchers/:code`. Voucher model `{ code (unique per scope), scope: 'platform'|'store', storeId?, type: 'percent'|'fixed'|'free_shipping', value (bps or minor), minSpend, maxDiscount?, startsAt, endsAt, usageLimit, perUserLimit, usedCount, followerOnly?, categoryIds?, productIds? }`.
- Pricing engine in `server/src/modules/orders/pricing.ts` — pure functions with unit tests: line totals, wholesale tiers, flash price, store voucher, platform voucher (prorated across stores by subtotal share, rounding remainder to the largest store), shipping per store (zone by buyer city; free above threshold; free_shipping voucher), coins redemption (Phase 8 hook, 0 for now).

## Checkout & order split
- `POST /checkout/preview { addressId, paymentMethod, notes?: Record<storeId,string>, coins?: number }` → same shape as cart summary but final, with per-store breakdown.
- `POST /checkout { addressId, paymentMethod, notes?, idempotencyKey }` →
  1. Re-price server-side (never trust client prices). 2. Atomically reserve stock per variant (`findOneAndUpdate` with `stock >= qty`, `$inc: {stock: -qty}`) — roll back already-decremented lines on any failure → 409 `STOCK_CHANGED` with details. 3. Create `Checkout {userId, number (SQ-YYMMDD-XXXXX), addressSnapshot, paymentMethod, paymentStatus, totals, orderIds, idempotencyKey (unique per user)}` + one `Order` per store `{ storeId, checkoutId, number (SQ-…-A/B), buyerId, items: [{productId, variantId, title, image, options, sku, price, qty, lineTotal}], subtotal, shippingFee, discounts: {store, platform}, total, commission: {bps, amount}, sellerNet, status: 'placed' (COD) | 'pending_payment' (online), timeline: [{status, at, by, note}], payment: {method, status}, shippingAddress, buyerNote, sellerNotes: [{by, at, text}], channel: 'online'|'pos', cancel?: {by, reason, at}, deliveryOtpHash?, riderId?, invoiceNumber }`. 4. Remove purchased items from cart, increment voucher usage, soldCount. 5. Emit socket `order:new` to the store room `store:{id}` (live alert with sound in Seller Center) and send emails (console).
  Same `idempotencyKey` returns the original checkout (no double order).
- Commission: `CommissionRule` resolution order store > category > global (seed global 10% = 1000 bps). Stored on the order at creation time.
- `GET /checkout/:number` (owner only) → success page data.

## Phase 6 — implementation notes & deviations (D-055..D-059)
- **Cart DTO additions:** `groups[].storeDiscount|platformDiscount|total`, `savedForLater: CartItem[]` (saved lines are NOT in `groups`), `summary.coins|selectedCount`, `freeShippingProgress[].threshold`, `issues[].details` (`{from,to}` for `qty_reduced` / `price_changed`), `CartItem.lineTotal|flash?`. Vouchers in the DTO: `{ code, scope, type, discount, valid, reason?: 'MIN_SPEND'|'NOT_ELIGIBLE' }`. Issues are reported once (the server then stores the new qty / last-seen price). `POST /cart/items` → 201. Merge keeps `max(existing, guest)` qty and silently skips unavailable lines.
- **Voucher errors:** 404 `VOUCHER_NOT_FOUND`, 400 `VOUCHER_EXPIRED|VOUCHER_EXHAUSTED|VOUCHER_USED|VOUCHER_NOT_ELIGIBLE|VOUCHER_MIN_SPEND` (`details.minSpend`), `CART_EMPTY`. One platform voucher + one voucher per store. Model also has `title`, `isActive`; `usageLimit: 0` = unlimited. Per-user usage is counted in `VoucherUsage`. `followerOnly` vouchers are unusable until follows ship.
- **Checkout:** `coins` is accepted (ignored, 0). Preview returns the cart DTO + `address`, `paymentMethod`, `paymentAvailable`, `canPlace`, `stores[]: {storeId, itemsSubtotal, storeDiscount, platformDiscount, shippingBase, shippingFee, total, note}`. `POST /checkout` → 201 (new) / 200 (same idempotencyKey replay) with `CheckoutDTO {id, number, paymentMethod, paymentStatus, totals, orders: OrderDTO[], createdAt}`. Errors: 409 `CART_CHANGED` (`details.issues`), 409 `STOCK_CHANGED` (`details.items`), 409 `VOUCHER_EXHAUSTED`, 400 `PAYMENT_NOT_CONFIGURED` (anything but COD), 400 `COD_NOT_AVAILABLE`, 400 `CART_EMPTY`, 404 `ADDRESS_NOT_FOUND`. Rate limited 30 / 10 min per user. Order also stores `discounts.shipping`, `vouchers {store?, platform?}`, `tracking?`, `stockRestored`.
- **Buyer orders:** list `meta: { nextCursor, counts: {to_pay, to_ship, ...} }`; detail adds `trackingSteps[{status, done, at, current}]`, `canCancel`, `checkoutNumber`, and `deliveryOtp` (buyer only, while shipped/out_for_delivery/failed_delivery). Buyers may also cancel `pending_payment`. Reorder → `{ data: CartDTO, meta: {added, skipped} }`. Other buyers' orders → 404.
- **Seller orders:** list `meta.counts` = `{ all, <every status> }` (counts respect `q/from/to`, not `status`). `q` searches number, buyer name/phone, item title/SKU. Status body: `{ to, note?, reason? (required for cancelled), tracking? }`. Bulk: `to: 'confirmed'|'packed'` only → `{ results: [{id, ok, error?}], updated }`. Notes → 201. Seller DTO adds `commission`, `sellerNet`, `sellerNotes`, `buyer {id, name}`; never the OTP. `assign-rider` requires the order to be packed or later. Invalid transitions → 409 `INVALID_TRANSITION`; lost race → 409 `ORDER_CHANGED`.
- **Socket:** `order:new {id, number, total, itemCount, createdAt}` and `order:updated {id, number, status}` on `store:{storeId}`; `order:updated` also on `user:{buyerId}`.

## Phase 9 follow-ups (cart summary, buyer filter)
- **Coins in the summary:** `summary.discountTotal` stays vouchers + shipping discounts only and does **not** include coins. Coins are shown separately: `summary.coinsDiscount` (minor units) and `summary.coinsUsed` (whole coins). `summary.coins` is kept as a deprecated alias of `coinsDiscount`. `summary.total = itemsSubtotal + shippingTotal − discountTotal − coinsDiscount`. A cart without `coins` requested (`GET /cart`) always has `coinsDiscount: 0`; `POST /checkout/preview {coins}` fills it (also per store in `stores[].coinsDiscount`). Orders show it as `discounts.coins`.
- **`GET /orders?store=<storeId|slug>`** (buyer): only orders with that store; `meta.counts` is scoped to it too. An unknown store returns an empty list (never 404).
- **`POST /cart/select-store {storeId, selected}`** (de)selects every non-saved item of one store.
